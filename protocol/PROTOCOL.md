# henry-hq 项目协议 v1

目的：让 Henry **只看需要他判断的东西**，其余由机器证明或由 agent 自主推进。

接入协议的项目，根目录有三份文件：

| 文件 | 谁写 | 给谁看 | 作用 |
|---|---|---|---|
| `STATUS.md` | agent 每轮收工更新 | Henry | 现状摘要 + 待判断清单，**不超过一屏** |
| `ACCEPTANCE.md` | Henry 定标准，agent 补检查命令 | agent / 机器 | 完成的定义 + 机器可执行检查 |
| `DECISIONS.md` | agent 记录，Henry 裁决 | agent | 已定下的产品/设计决定，**开工必读，不许回退** |

`.hq/`（已加入 .gitignore）存放机器产物：`verify.json`、检查日志、闸门状态。

## 开工

1. 读 `STATUS.md`、`DECISIONS.md`、`ACCEPTANCE.md`（再读项目自己的协议文件）。
2. 处理 `❓` 里 Henry **已勾选或已批注**的条目：
   - 批注里含品味/设计取舍 → 提炼成一条 `DECISIONS.md` 记录；
   - 然后把该条从 `❓` 移除（或按批注继续做）。

## 收工（Stop 闸门会检查）

1. 跑 `hq verify`（默认 quick 档；交付性改动跑 `hq verify --tier full`）。
   **不要自己往 ✅ 区写“已通过”**——那一块由 `hq verify` 生成，agent 写的不算证据。
2. 更新 `STATUS.md`：
   - front matter 的 `updated`；
   - `> 一句话现状`（≤ 2 行，写结果不写过程）；
   - `❓ 待 Henry 判断`：只放**机器验证不了、必须他的眼睛/耳朵/手/品味/权限**的事。
     每条写清：看什么、怎么看（命令/链接/截图路径）、你的建议。
     格式：`- [ ] <事项> — 怎么验：… — 建议：…`
   - `⛔ 阻塞`：缺权限/缺信息/外部依赖，写明需要谁做什么；
   - `▶ 下一步`：你将自主推进的事，**不需要 Henry 回复**。
3. 过程细节写进项目自己的日志（如 `iteration.md`、`PROJECT_STATUS.md`），不要塞进 STATUS。

## Stop 闸门（hooks 自动执行）

agent 想结束一轮时，`hq gate` 会：

1. 代码自上次通过后有变更 → 跑 quick 检查；失败则**驳回结束**，把失败输出交还 agent。
2. 代码有变更但 `STATUS.md`（除机器区外）没更新 → **驳回结束**，要求按上面第 2 步更新。
3. 同一轮最多驳回 2 次，之后放行并在 `.hq/gate.log` 记一笔，晨报会标红。

## Henry 怎么验收

- 看晨报/晚报（`hq brief`）或 tokei「项目」面板里的 ❓ / ⛔ / ✅ 计数。
- 在 `STATUS.md` 里直接操作：`- [x]` 表示通过；在条目后写 `→ Henry: …` 表示批注/不通过。
- 不需要再说「继续」「展示成果」——`▶ 下一步` 就是默认授权。
