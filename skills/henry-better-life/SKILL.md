# henry-better-life（AI 原生测试与确定性工程工作流）

核心目标：**最大化节约用户注意力（不靠人盯终端、不靠人翻千行代码与流水账），同时以可复现的机器检查与靶向证据，把 Agent 交付的可信度锚定到确定性机制而非“模型自觉”。**

---

## 一、默认自主与注意力契约

1. **默认授权执行**：用户的指令与 `▶ 下一步` 即授权。仅在「缺失外部凭据 / 不可逆高危或资金生产操作 / 确实存在主观审美或产品分歧」三种情形提请拍板；严禁假性请示（`timid pause`）或“只在文档加一句注意”。
2. **一屏分级交付**：**80%–90%** 的客观代码、状态机、布局、多语言与单测问题由 Agent 自主验证闭环；仅把依赖物理硬件体感、真人入镜、主观审美或账号授权的 **10%–20%** 留给用户（写入 `STATUS.md` 的 `❓`），每项附 `怎么验 / 预期 / 建议`。
3. **结论先行 + 真实证据**：汇报只列真实跑过的检查命令、Commit SHA、实测数量与失败范围；明确区分 `physical` 与 `emulator`，严禁拿模拟器、跳过用例或旧构建冒充当前结论。

## 二、P0 / P1 / P2 工程与测试原则（强固化清单）

### P0-1 · 纠偏即 Lint，不再往说明文档堆话
- **痛点**：把教训写进 `AGENTS.md` / `CLAUDE.md`，下一轮或换个模型照样忘；说明文档越堆越厚，反而挤占上下文。
- **规则**：**每被纠正一次 AI 错误，立刻写成确定性自动检查规则**（`add-rule` / `<200ms` 静态不变量 + 可咬合单测），挂载进 `pre-commit` 与 `Stop` 钩子；规则不通过，代码提交不上去、回合结束不了。
- **防误报/漏报与连带扫描**：
  - 每条规则必须自带正例（`badExamples` 必拦截）与反例（`goodExamples` 必放行）自检。
  - 修复单点问题时强制扫描相邻调用链（如生命周期作用域、国际化接口禁传预插值字符串、弹窗密度适配包装、主线程状态安全与并发边界），一次性把同类隐患锁进静态检查。

### P0-2 · 80/20 局部靶向录屏 + 盲模态遥测 + 一页审阅卡
- **痛点**：全程录屏把 80% 时长浪费在冷启动、赋权、登录与多级页面跳转上；只看源码自证或纯视觉录屏，既拖慢 Agent，也让无视觉模态或弱 GUI 操控能力的 Agent 难以自检。
- **规则（靶向局部录屏优先，全功能冒烟其次）**：
  1. **前置就位不进视频**：把权限授予、语言切换、Activity/路由直跳、测试夹具准备收口为静默 `setup` 预设，不录制一帧废片；
  2. **模块化极简动作原语 + 短片段录屏（2–6s）**：提供语义选择器、方向滑动与断言简写，只在核心修复动作前后起停录制 H.264 短片（开启指针触控可视化并在结束后还原）；
  3. **盲模态“像素转文本”遥测摘要（`agent-digest.md`）**：自动从前后截图与 UI/DOM 树计算文本增删 Diff、非目标语言字符漏翻（如英文模式残留 CJK）、兄弟文本边界重叠、节点像素级对比度与前后画面变化率——即使纯文本模型也能直接抓出白底白字或遮挡溢出；
  4. **1 页单文件审阅卡（`review.html`）**：聚合 Commit SHA、运行载体（如 `emulator`）、短片播放与关键帧，让用户 5–15 秒扫完签收，校验器自动拦截“过期 SHA 伪收据”和“桌面/纯色无效截图”。

### P1-1 · 代码库与文档记忆防膨胀（去杂草、拒 CRUD 堆积）
- **痛点**：下一轮 Agent 学习代码风格的主要材料就是当前仓库本身。零引用的废脚本和编年流水账文档，会被后续 AI 当成惯例照抄并迅速污染上下文。
- **动作**：
  - **归档清理**：清理零引用的一次性排查脚本（移入归档或删除）；保持目录边界清晰。
  - **文件行数棘轮（Ratchet）**：对历史大文件设只降不增的上限，对新模块设默认行数上限，倒逼拆分单责模块。
  - **文档记忆融合，拒绝 CRUD 流水账**：`STATUS.md` / `DECISIONS.md` / `ACCEPTANCE.md` 只保留按领域蒸馏融合后的当前记忆；过期全文带 SHA256 归档至 `.hq/history/` 移出上下文，并用 `docMemoryHygiene` 预算门禁限制行数、禁止顶部摘要含裸长 URL、禁止堆积 `[x]` 已决项与按日期追加的 `## D-xxx` 条目。

### P1-2 · 物理封禁易错工具链，用机制替代自觉
- **痛点**：多人/多 Agent 并发下最易翻车的环节（抢物理设备、并发跑坏构建缓存、误用双栈随机端口、绕过事务层直改数据库、跨线程写 UI 状态），靠口头约定必然反复出事。
- **动作**：凡是人类都常错、AI 更用不好的环节，直接封死旧入口或加硬锁：
  - **构建锁 + 自动自举**：把 JDK/环境探测与文件级互斥锁收口进底层构建包装器，拦截从废弃目录构建。
  - **共享设备身份锁**：外部设备命令统一走带独占锁和身份标识的 wrapper，Linter 直接报错禁止脚本绕过封装或依赖易断的相对路径。
  - **API 与写法禁区**：通过词法级 Lint 在提交前物理禁用已知坑点（如测试服务裸写 `listen(0)` 引发双栈端口碰撞、国际化传预插值字符串、空 `catch {}`、非受控后台协程/阻塞等待、绕过 repository CAS 直写底层集合）。

### P2 · 消除绝大多数代码注释（代码与测试即唯一真相）
- **痛点**：Agent 时代业务代码高频重构，没人会顺手维护叙述性注释。过时注释会误导下一轮 AI 按错误假设改代码，甚至出现“单测断言注释文本”的耦合缺陷。
- **边界与执行**：
  - **保留**：需要人工查看与填写的**配置文件**（`.toml`/`.json`/`.env.example`/构建与 CI 配置）、协议头、`#!`、合规声明与 Lint 指令注释。
  - **剥离与拦截**：用词法级工具（严格区分字符串、URL、Shader 与真实注释）批量剥离生产业务源码中的叙述性注释；在 `pre-commit` 与 `Stop --worktree-diff` 钩子中对比 `HEAD` 拦截新增叙述性注释，迫使代码用清晰命名、强类型与可执行单元测试表达意图。

## 三、跨 Harness 与工程基建有机融合（`HQ` × Hooks × Task Runner）

1. **统一确定性命令入口（如 `justfile` / `Makefile` / npm scripts）**：封装 `context`、`invariants`（`<200ms` 静态门禁）、`test`（带锁+环境+自动提取失败源码行号）、`preflight`、`add-rule`、`record-clip`（80/20 局部录屏）、`strip-comments`、`probe` 与 `hq verify`。`ACCEPTANCE.md` 的 `hq-checks` 直接复用同一组命令，避免两套检查分叉。
2. **多 Harness 同源适配（Codex CLI / Claude Code / DSH / Orca）**：
   - **指令同源**：以 `AGENTS.md` 为唯一准则入口，`CLAUDE.md` 通过符号链接或 `@AGENTS.md` 指向同一文件。
   - **Hook 兼容与去重**：`.codex/hooks.json`、`.claude/settings.json` 与底层 Hook 脚本归一化 `Bash|bash|shell|exec_command` 工具名并解析数组命令；通过 `git rev-parse --show-toplevel` 从 `cwd` 动态解析隔离 worktree，消除对宿主机绝对路径与特定目录名的依赖；`Stop` 中快检（`<200ms` 不变量与 `--worktree-diff` 未暂存增量检查）与单次 `hq gate` 各跑一次、互不重复。
   - **并发与阶段隔离**：多任务按独立 worktree 并行，公共胶水文件与根级 HQ 状态文件保持单写者集成；只读分析/审阅阶段自动跳过写门禁。

## 四、落地执行流程（触发本 Skill 时按序推进）

1. **确定性诊断**：先跑 `hq diagnose` 或扫描仓库脚本、文档体积、Hooks 与高频踩坑点，不凭空拍脑袋提方案。
2. **分批改造**：按 **P0（Lint 护栏 + 80/20 局部录屏/遥测审阅卡）→ P1（清杂草 + 禁易错入口 + HQ 记忆融合）→ P2（词法去注释 + 增量阻断）** 推进；多独立模块优先独立 worktree 并行改造与核验。
3. **跨 Harness 对齐**：校验根与子仓的 `AGENTS.md` / `CLAUDE.md` / `.codex/` / `.claude/` / `ACCEPTANCE.md`，跑通 `hq doctor`。
4. **全量自验与一屏交付**：运行不变量门禁、规则正反例单测、全套单测与 `hq verify --tier quick`，按「已闭环事项 + 仅需用户拍板项」一屏交付结果与可点击链接。
